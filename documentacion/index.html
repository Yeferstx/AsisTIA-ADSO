1. Introducción

AsistIA SENA es un sistema que lleva la asistencia de la ficha 3237831 de forma automática. Cuando un aprendiz llega al ambiente, una cámara reconoce su cara, una estación con un ESP32 en la puerta le abre la talanquera y le muestra en una pantalla si llegó a tiempo o tarde, y un servidor guarda la llegada para que el instructor la vea en una página web.

Problema que soluciona

Llamar a lista toma tiempo de la clase, se presta para que alguien responda por otro y después hay que pasar todo a mano a un Excel. Además, avisarle a cada ausente, llevar la cuenta de las fallas y decidir a quién le toca el aseo son tareas que el instructor hace todos los días.

Objetivo

Automatizar la asistencia de la clase: registrar las llegadas con reconocimiento facial, avisar por Telegram a los ausentes y al instructor, generar el Excel, sortear el aseo y darle al instructor un panel web donde pueda ver y controlar todo, con ayuda de inteligencia artificial (Gemini) para revisar excusas y responder preguntas.

4. Funcionalidades del sistema

4.1 Reconocimiento facial

Primero se registra a cada aprendiz con capturar_rostros.py, que toma 50 fotos de su cara en escala de grises. Luego entrenar.py enseña al reconocedor LBPH con esas fotos. Durante la clase, reconocer.py mira la cámara: si la misma cara sale varias veces seguidas con una distancia menor al umbral, la registra una sola vez como A_TIEMPO o TARDE según el horario, y publica el registro por MQTT. Si no la reconoce, publica DESCONOCIDO (máximo cada 10 segundos para no llenar el broker).

4.2 Estación de la puerta (ESP32)

• El PIR detecta a alguien y la pantalla muestra "Mire la camara".

• Cuando llega el registro: si es A TIEMPO prende el LED verde, si es TARDE el rojo, muestra "Bienvenido" y el nombre, y el servo abre la talanquera. Si es desconocido muestra "NO REGISTRADO" y no abre.

• El ultrasónico cuenta las personas que pasan y el táctil abre o cierra la asistencia.

• El relé prende la luz del salón y se apaga a la hora de salida.

4.3 Servidor y bot de Telegram

• Guarda cada llegada en asistencia.json (no guarda a los desconocidos ni repite a alguien que ya llegó).

• A la hora de cierre: le escribe a cada ausente para que mande su excusa, le manda al instructor el resumen y el Excel, y hace el sorteo del aseo en el grupo.

• Las excusas y los permisos de salida los resume Gemini y sugiere si son válidos, pero el que decide es el instructor, en Telegram o en la página.

• Avisa si alguien lleva 3 fallas seguidas (riesgo de deserción) y anima a quien lleva 2 llegadas tarde en la semana.

• Comandos del aprendiz: /start, /fallas, /aseo, /permiso y /ayuda. Del instructor: /hoy, /excel y /cerrar.

4.4 Panel web del instructor

4.5 Sorteo del aseo

Le toca a los 3 últimos que llegaron tarde. Si llegaron tarde menos de 3, se completa con ausentes al azar. Las tareas (Trapero, Escoba y Trapito) se reparten al azar entre ellos. Si nadie llegó tarde ni faltó, se avisa en el grupo que no hay aseo.

4.6 Horario editable

El instructor cambia desde la página la hora de apertura, la hora límite (después es tarde), la salida y el cierre. Se guarda en horario.json; el servidor lo revisa cada minuto y reconocer.py lo pregunta al servidor cada minuto, así todos usan la misma hora.

Mejora: Se probó con la LCD conectada: el ESP32 se conectó al WiFi, al broker y mostró los mensajes.

6. Explicación del código

6.1 Cámara: decidir si llegó a tiempo o tarde

En reconocer.py, calcular_estado() compara la hora actual con la hora límite. Antes de comparar llama a actualizar_horario(), que como máximo una vez por minuto le pregunta el horario al servidor; si el servidor no responde, sigue con el último horario que tenía.

reconocimiento/reconocer.py

def calcular_estado():

    actualizar_horario()

    ahora = datetime.now().strftime("%H:%M")

    if ahora <= HORA_CORTE:

        return "A_TIEMPO"

    return "TARDE"

 

Las horas se comparan como texto ("12:25" <= "12:30") y funciona porque siempre tienen dos dígitos.

6.2 ESP32: qué hace cuando llega un registro

esp32/src/main.cpp (resumido)

if (estado == "A_TIEMPO") {

  cambiarLeds(true, false);

  abrirTalanquera(nombre, "A TIEMPO");

} else if (estado == "TARDE") {

  cambiarLeds(false, true);

  abrirTalanquera(nombre, "TARDE");

} else {

  cambiarLeds(false, true);

  mostrar("NO REGISTRADO", "Acceso negado");

}

 

El mensaje llega como JSON ({"nombre", "hora", "estado"}), se lee con ArduinoJson y según el estado se prende un LED, se abre el servo y se escribe en la pantalla.

6.3 Servidor: guardar una llegada

servidor/src/telegram/telegram.service.ts

guardarLlegada(registro: Registro) {

  if (registro.nombre === 'DESCONOCIDO') {

    return;

  }

  const asistencia = leerJson('asistencia.json', {});

  const dia = this.leerDia(asistencia, fechaHoy());

  const yaLlego = dia.registros.some((r: Registro) => r.nombre === registro.nombre);

  if (dia.cerrada || yaLlego) {

    return;

  }

  dia.registros.push({ nombre: registro.nombre, hora: registro.hora, estado: registro.estado });

  guardarJson('asistencia.json', asistencia);

}

 

No guarda a los desconocidos, ni a alguien que ya llegó, ni si la asistencia ya se cerró.

6.4 Servidor: el horario se revisa cada minuto

servidor/src/telegram/telegram.service.ts (resumido)

cron.schedule(`* * * * ${DIAS_CLASE.join(',')}`, () => this.revisarHorario());

 

revisarHorario() {

  const horario = leerHorario();

  const ahora = new Date().toTimeString().slice(0, 5);

  if (ahora == horario.apertura) { /* publica ABRIR */ }

  if (ahora == horario.salida) { /* publica APAGAR_LUZ */ }

  if (ahora == horario.cierre) { this.cierreAutomatico(); }

}

 

El "* * * * 1,2,3,4,5" de node-cron significa "cada minuto, de lunes a viernes". Como el horario se lee del archivo cada vez, si el instructor lo cambia se usa de una vez.

6.5 Sorteo del aseo

servidor/src/telegram/asistencia.ts

export function sortearAseo(tardes: string[], ausentes: string[]) {

  const lista = tardes.concat(revolver(ausentes));

  const tareas = revolver(TAREAS);

  const asignados: Asignado[] = [];

  for (let i = 0; i < lista.length && i < 3; i++) {

    asignados.push({ nombre: lista[i], tarea: tareas[i] });

  }

  return asignados;

}

 

Antes de llamarla, el servidor ordena a los que llegaron tarde del último al primero (sort con localeCompare de la hora). Por eso los 3 primeros de la lista son los 3 que llegaron más tarde; los ausentes van después, revueltos.

6.6 Login: revisar la sesión en cada pedido

servidor/src/sesion.ts

export function revisarSesion(req: Request, res: Response, next: NextFunction) {

  const ruta = req.path;

  const libres = ['/login.html', '/login.js', '/estilos.css', '/img/asistia.png', '/api/login'];

  const leerHorario = ruta == '/api/horario' && req.method == 'GET';

 

  if (libres.includes(ruta) || leerHorario || haySesion(req)) {

    return next();

  }

  if (ruta.startsWith('/api/')) {

    return res.status(401).json({ mensaje: 'Primero inicia sesion' });

  }

  return res.redirect('/login.html');

}

 

Es un middleware: una función que se ejecuta antes de cada pedido. Si el pedido es del login, de leer el horario (lo necesita reconocer.py) o trae una sesión válida, lo deja pasar con next(). Si no, a la API le responde 401 (no autorizado) y a la página la manda al login. La sesión es un código aleatorio (crypto.randomUUID()) que se guarda en una lista del servidor y en una cookie del navegador.

6.10 Página: proteger el HTML

servidor/public/app.js

function limpiar(texto) {

  return String(texto || '').replace(/&/g, '&').replace(/</g, '<')

    .replace(/>/g, '>').replace(/"/g, '"');

}

 

Lo que escriben los aprendices (excusas, permisos) se pasa por limpiar() antes de ponerlo en la página. Así, si alguien escribe código HTML en una excusa, se muestra como texto y no se ejecuta.


7. Funcionamiento general

7.1 Paso a paso de un día de clase

1. A la hora de apertura (12:00 por defecto) el servidor publica ABRIR en MQTT y la estación queda lista.

2. Llega un aprendiz: el PIR lo detecta y la pantalla dice "Mire la camara".

3. reconocer.py reconoce la cara y publica {"nombre", "hora", "estado"} en sena/asistencia/registro.

4. El ESP32 recibe el mensaje: prende el LED, abre la talanquera y muestra el nombre y el estado.

5. El servidor recibe el mismo mensaje y lo guarda en asistencia.json.

6. El panel web, que pregunta cada 2 segundos, muestra la llegada con una animación y un aviso.

7. A la hora de salida se apaga la luz; a las 5:00 p. m. se recuerda el aseo en el grupo.

8. A la hora de cierre (o cuando el instructor oprime "Cerrar asistencia ahora" y confirma): se marca a los ausentes, se les escribe por Telegram, se le manda el resumen y el Excel al instructor y se publica el aseo en el grupo.

9. Si un ausente responde con una excusa, Gemini la resume y sugiere si es válida; el instructor la acepta o la rechaza y al aprendiz le llega la respuesta.

8. Seguridad

Estas son las medidas que de verdad tiene el proyecto:

Medida

Por qué es importante

Login del instructor con usuario y clave en el .env.

Sin entrar no se ven los datos ni se puede cerrar la asistencia.

Middleware revisarSesion en el servidor.

La protección está en el servidor, no solo en la página: aunque alguien llame a la API directamente, recibe 401.

Cookie httpOnly con un código aleatorio.

El JavaScript de la página no puede leer la cookie de la sesión.

Claves en el .env y en secretos.h.

No quedan escritas en el código y no se suben a GitHub (.gitignore).

MQTT con TLS y certificado del broker.

Los mensajes viajan cifrados y el ESP32 y Python comprueban que hablan con el broker correcto.

Función limpiar() en la página.

Evita que un texto escrito por un aprendiz se ejecute como HTML (ataque XSS).

Revisión de la fecha antes de crear el Excel.

La fecha se usa en el nombre del archivo; se revisa que sea como 2026-11-20 para que no se pueda usar otra ruta.

Comandos solo para el instructor en Telegram.

/hoy, /excel y /cerrar revisan que el chat sea el del instructor.

Ventana de confirmación antes de cerrar.

Cerrar manda mensajes que no se pueden borrar.

Gemini solo aconseja.

La decisión sobre excusas y permisos siempre es del instructor.

 

Lo que se podría mejorar

• La clave del instructor está en el .env como texto normal; se podría guardar cifrada (hash).

• Las sesiones se guardan en la memoria del servidor: si se reinicia hay que volver a entrar.

• No hay límite de intentos en el login; se quitó para dejarlo sencillo.

• En la red local la página va por http, no por https.

10. Conclusiones

AsistIA SENA une varias tecnologías en un solo sistema: visión por computador con Python, electrónica con el ESP32, comunicación con MQTT, un servidor en NestJS, un bot de Telegram, inteligencia artificial con Gemini y una página web. Con eso se logró que la asistencia se tome sola, que los ausentes y el instructor se enteren por Telegram, que el Excel y el aseo salgan automáticos y que el instructor tenga un panel seguro, cómodo y que también funciona en el celular.

Durante el trabajo también se aprendió a probar sin el hardware (con el simulador), a comprobar el diseño en muchos tamaños de pantalla y a dejar el código sencillo para poder explicarlo.

Mejoras para el futuro

• Usar una base de datos (por ejemplo MySQL o MongoDB) en vez de archivos JSON si crece la cantidad de fichas.

• Guardar la clave del instructor cifrada y usar https.

• Permitir varios instructores y varias fichas.

• Mejorar el reconocimiento facial con más fotos o con un modelo más moderno.

• Que la página pueda abrir la asistencia y controlar la maqueta desde el panel.

Preguntas que podría hacer el instructor

1. ¿Por qué usaron MQTT y no que todo le hable directo al servidor?

Porque MQTT está hecho para dispositivos como el ESP32: es liviano y funciona con "publicar y escuchar". La cámara publica una sola vez la llegada y al mismo tiempo la reciben el ESP32 y el servidor, sin que la cámara tenga que saber quién está escuchando.

2. ¿Cómo reconoce la cara?

Primero el detector Haar de OpenCV encuentra dónde está la cara en la imagen. Luego el reconocedor LBPH, que entrenamos con 50 fotos de cada aprendiz, dice a quién se parece y qué tan parecida es (la distancia). Si la distancia es menor al umbral y sale varias veces seguida, se registra.

3. ¿Qué pasa si llega alguien que no está registrado?

reconocer.py publica DESCONOCIDO, el ESP32 muestra "NO REGISTRADO", prende el LED rojo y no abre la talanquera. El servidor no lo guarda.

4. ¿Dónde guardan los datos? ¿Usan base de datos?

No usamos base de datos. El servidor guarda todo en archivos JSON en la carpeta servidor/datos, con dos funciones: leerJson y guardarJson. Para una ficha es suficiente; si creciera usaríamos una base de datos.

5. ¿Cómo se conecta la página con el servidor?

La página es HTML, CSS y JavaScript que entrega el mismo servidor. Con fetch le pide los datos a las rutas /api/... Por ejemplo, cada 2 segundos llama a /api/estado y dibuja las llegadas.

6. ¿Qué seguridad tiene?

La página tiene login: el usuario y la clave están en el .env. Al entrar el servidor guarda un código en una cookie httpOnly y un middleware revisa ese código en cada pedido; sin él, la API responde 401. Además MQTT va con TLS, las claves no están en el código y la función limpiar() evita que un texto se ejecute como HTML.

7. ¿Cómo decide a quién le toca el aseo?

Ordena a los que llegaron tarde por la hora y toma a los 3 últimos. Si llegaron tarde menos de 3, completa con ausentes al azar. Las tareas Trapero, Escoba y Trapito se reparten al azar. Eso está en la función sortearAseo y tiene pruebas automáticas.

8. ¿Qué hace la inteligencia artificial?

Usamos la API de Gemini para tres cosas: resumir las excusas y decir si parecen válidas, resumir los permisos de salida y responder las preguntas del chat del panel con los datos de asistencia. Pero solo aconseja; el que decide es el instructor.

9. ¿Qué dificultades tuvieron?

OpenCV 5 ya no traía el detector Haar y tocó usar la versión 4. El ESP32 no se conectaba al hotspot del iPhone hasta que le borramos la memoria. Al principio el reconocimiento confundía a otras personas con uno, y lo mejoramos pidiendo que la cara salga varias veces seguidas y ajustando el umbral. Y una vez se cerró la asistencia sin querer, por eso hicimos la ventana de confirmación.

10. ¿Cómo comprobaron que funciona?

Con pruebas automáticas (npm test, 6 pruebas del aseo y las fechas), con el simulador del ESP32 para probar sin la maqueta, y revisando la página en 9 tamaños de pantalla, en modo claro y oscuro. Cuando simplificamos el código comparamos capturas de antes y después y quedaron iguales.
